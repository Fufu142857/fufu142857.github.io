### Bag-of-Words

#### 1 Introduction

* **动机 (Motivation)**: 图像底层的像素值本身是一堆缺乏语义 (Semantic) 的数字，这使得直接使用像素进行 Image classification (图像分类) 极其困难。我们需要为图像寻找一种更具表达力的 **Representation (表示)** 。

* **基本思想 (Bag-of-features)**:
  * 将物体或图像视为一组 **Local features (局部特征)** 的无序集合。这种做法就像数学上的集合，彻底丢弃了特征之间的 **Spatial layout (空间位置信息)** 。
  > 无序
  * **直观类比**: 就像我们要判断一张图是不是人脸，不再去关心五官的精确排列，而是只要在这张图里数出“两只眼睛、一个鼻子、一张嘴”，就断定它是人脸。虽然听上去很疯狂且丢失了大量信息，但这被证明是非常强大的工具。

* **优势**: 抛弃空间结构关系后，模型对物体的 **Occlusion (遮挡)** 变得极其鲁棒 (Robust)。结合 SIFT 等高级局部特征，可以自带 Scale invariance (尺度不变性) 和 Rotation invariance (旋转不变性)。

* **文本分析溯源**: 这种思想最早源于自然语言处理中的文本分类。比如判断两篇文章的内容，可以通过建立 Histogram (直方图)，去统计“机器人”、“CMU”、“关节”等关键字出现的频率，用这个词频向量就能判断文章主题。在早期计算机视觉中，也用类似思路分析卫星图上的森林、城市等，提取出基本的纹理元素 (Texton) 来做分类。

#### 2 Pipeline to construct BoW
把图像转化为特征向量，主要分为三个核心步骤。

**1. Feature Extraction (特征提取)**
* 给一张图像，首先在图像上（可以通过规则网格 Grid，或者基于 SIFT 的关键点检测算法）提取出大量的 Local feature，每个特征包含一个高维的 Descriptor (描述子，如 128 维的向量)。

**2. Dictionary Learning (字典学习)**
* 就像文本是由英文字典里的单词组成一样，我们需要先定义出图像世界里的基础 **Visual Words (视觉单词)** ，它们构成了 **Visual Vocabulary / Dictionary (视觉字典)** 。
* **K-means Clustering (K-均值聚类)**: 将训练集里提取出的成千上万个 Feature 映射到高维特征空间中，并使用 K-means 算法对它们进行 **Cluster (聚类)** 。
  * **聚类原理**: 我们希望把相似的特征（比如因视角轻微变化或光线变化导致的不同的“眼睛”特征）聚合成一堆，统一视作一个 Visual Word。
  * **K-means 过程**: 预先设定把数据分成 K 类。随机给定 K 个初始中心点 (Centroid) $\rightarrow$ 算出每个样本到中心点的距离并分配给最近的中心 $\rightarrow$ 算出被分配在一堆的样本的平均值，作为新的中心点 $\rightarrow$ 不断迭代直到收敛。最终得出的这些中心点 (Centroids) 就是我们的 Visual Words。
* **Hierarchical K-means (层次 K-means)**: 当需要的 Visual Word 数量极大 (如 10 万个) 时，为了加速将新特征匹配到对应单词的过程，可以采用树状的分层结构。先聚合成 10 大类，在每个大类下再聚合成 10 小类，层层递进，极大提升映射速度。

**3. Encoding (图像编码)**
* 字典建好后，对于任意输入的新图像，将其提取出的每一个 Local feature 映射到字典中最接近的 Visual Word 上。
* 统计这幅图里每个 Visual Word 出现了多少次，最终形成一个一维的 **Feature Vector / Histogram (特征向量 / 直方图)** 。用这个向量就能输入给分类器 (如 SVM) 进行识别。

#### 3 Large-scale Image Search

除了分类，BoW 常被用于 **Instance-level recognition (实例级识别)** 或基于内容的图像检索。例如在 10 万个游戏/CD 封面数据库中，快速找出一张用户上传的手机实拍封面。为此，需要引入两个极其重要的技术：

**1. TF-IDF 权重 (加权策略)**
* 并不是每个单词都同等重要。就像英文中的 "the"、"and" 每一页都有，不包含什么有效信息；而在所有图像中都频繁出现的 Visual Word 也缺乏特异性，对我们区分物体没有价值。
* **TF (Term Frequency, 词频)**: 该 Visual Word 在**当前查询图像**中出现的次数。出现越多，权重越大。
* **IDF (Inverse Document Frequency, 逆文档频率)**: 公式为 $\log(\frac{N}{n_j})$。其中 $N$ 是数据库总图片数，$n_j$ 是包含该单词的图片数。如果一个特征在所有 10 万张图片里都出现过，除法结果为 1，取 Log 后为 0，赋予最低权重；如果在极少数图片里才出现，就会获得极高的权重。
* 最终权重为 TF 乘上 IDF，这样能凸显出那些真正具有区分度的特征。

**2. Inverted File / Index (倒排表加速)**
* 直接拿 Query 图像的 10 万维特征向量去跟数据库里 10 万张图逐一计算距离，计算量极其恐怖。
* **稀疏性 (Sparsity)**: 一张图像可能只有几千个特征，这意味着 10 万维的特征向量里绝大多数维度的值都是 0。
* **倒排表机制**: 离线建库时，为每一个 Visual Word 建立一个数组，专门记录这个单词在**哪些目标图像 (Document IDs)** 里出现过。
* 检索时，只需查看 Query 图像里实际出现了哪几个 Visual Word。把这几个词对应的目标图像列表调出来，进行求交集 (Intersection) 操作。这能把需要进行精确匹配的候选者从 10 万个瞬间缩减到几十上百个，从而实现实时级的搜索速度。

#### 4 Limitations and Applications

* **局限性**: 
  * 由于彻底丢掉了空间结构 (Spatial layout)，检索结果偶尔会出现不合常理的误匹配。例如，一面没有尖顶的墙，可能会因为局部特征高度重合，而被错误匹配给一面有尖顶的墙。
  * **因为高度依赖底层特征 (如 SIFT)，所以面对巨大的光照改变 (如拿晚上的照片去搜白天建库的照片)，算法往往会失败。**

* **在 SLAM 中的应用 (Relocalization / 重定位)**:
  * 在 SLAM 运行中，相机常因运动模糊或遮挡导致跟踪丢失 (Lost)。此时可以将当前帧作为 Query image，利用 BoW 技术在历史建好的 **Keyframe (关键帧)** 数据库中进行搜索。找到高度相似的关键帧后，恢复特征匹配并解算出相机 Pose，让系统满血复活。

* **在大规模三维重建中的应用 (如 Build Rome in a Day)**:
  * 从网上下载了 100 万张罗马的无序风景照要进行重建，如果两两提取特征做 Exhaustive feature match，计算量需要数百年。
  * 通过 BoW 做预检索，让每张图片只与其通过倒排表找出的最相似的 Top-50 张图片进行精细的 Feature match。这砍掉了惊人的计算量，能在极短时间（一天）内完成整个罗马城的三维重建。
